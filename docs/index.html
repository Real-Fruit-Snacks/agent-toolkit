Install

  1. Get the scripts

    Clone this repo, or download repo--agent-toolkit-*.zip from the latest release and extract it. Run the rest from its root.

  2. Download the release

    .\scripts\download-release.ps1 -To C:\toolkit-assets

    Every asset into one folder, through the GitHub CLI if it's there and plain HTTPS if not. A file already there is kept only if its hash matches.

  3. Check it and restore the folders

    .\scripts\unpack-release.ps1 -From C:\toolkit-assets

    Checks every file against SHA256SUMS.txt, joins the distro's parts and checks the result, then puts each asset back into windows\, linux\, wsl\ or caches\.

  4. Install, from an elevated PowerShell

    .\scripts\install-windows.ps1

    Installs the apps silently, restores the tool and browser caches, installs the MCP servers, plugins and skills offline, seeds config only where none exists, and sets the variables that turn off the updaters and telemetry. Open a new terminal afterwards.

    .\scripts\setup-wsl.ps1

    Installs WSL from the bundled MSI and imports ubuntu-dev, a distro that already has Git, Node, the GitHub CLI and the Claude Code CLI inside it. The first time WSL is turned on, Windows may want a reboot.

    sudo bash scripts/install-linux.sh

    For a standalone Debian or Ubuntu machine, with linux/ and caches/ restored: installs T3 Code from the .deb and provisions the same tools as the WSL distro.

Why pin everything

Each of these tools fetches something the first time it runs: an updater, a headless browser, a device agent, a model manifest. On a machine that should stay on one known build, or talk to one endpoint, those fetches are the problem. The release carries them all.

The install sets these as user environment variables, among others. The full list, with what each one turns off, is in config/env-vars.md.

T3CODE_DISABLE_AUTO_UPDATE=1
T3CODE_TELEMETRY_ENABLED=0
DISABLE_AUTOUPDATER=1
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1
npm_config_offline=true
PIP_NO_INDEX=1

The Claude Code provider's endpoint is set per instance in T3 Code, under Settings, Providers, Claude. Templates for an Anthropic-compatible gateway, Bedrock and Vertex are in config/claude-provider-env.example.

How a release is built

By weekly-release.yml, on GitHub's runners. It publishes only after every check below has passed; a failed check stops it before anything is published.

  1. schedule Sundays, 08:00 UTC

    Start

    On its own every week, or by hand from the Actions tab with a pinned T3 tag or Claude Code version, and publishing off to leave a draft for review.

  2. collect Windows runner

    Fetch everything

    collect.ps1 downloads the newest T3 nightly, Claude Code, the installers, the plugin marketplaces, the MCP servers and every cache, and reconciles the versions.

  3. distro Ubuntu runner

    Bake the Linux side

    Builds the Linux wheelhouse natively and the provisioned Ubuntu image in a chroot, then opens the image and checks it: the default MCP servers registered, at least 12 plugins enabled, the skills and binaries in place.

  4. publish Windows runner

    Install, pack, verify, publish

    Runs the T3 and Claude Code binaries and check-pins.ps1, then install-windows.ps1 on the clean runner and checks what it registered. Writes VERSIONS.md, packs the assets and cuts any of 1900 MiB or more into parts, uploads a draft, and has verify-release.ps1 compare every digest GitHub recorded with SHA256SUMS.txt. Only then it publishes, and rewrites this page.

Tested on

  • Windows 11 Pro 26300 with Windows PowerShell 5.1: the bake, collect and pin checks run here.
  • Ubuntu 24.04 noble under WSL 2: the distro is baked and its contents checked here.
  • A clean GitHub Actions Windows runner: every weekly build runs the install script there and checks the MCP servers, plugins, language servers and skills before it publishes.
  • Not tested: a full install from the release assets on a second physical machine, end to end.

Known issues

  • The app installers run with silent flags that are right for the pinned versions; a newer installer may change them.
  • T3 Code pins its on-demand tool versions per build. After bumping T3, run scripts/check-pins.ps1 -Fix, or the cache is ignored and a download is attempted.
  • Importing the raw Ubuntu rootfs instead of the baked distro needs a network to fetch the Playwright browsers.
  • On Linux without PowerShell, join the distro by hand: cat name.part1 name.part2 name.part3 > name, then sha256sum -c name.sha256.
  • The Docker MCP server is Windows-only; its dependencies don't resolve on Ubuntu's Python 3.12.
