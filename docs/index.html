agent-toolkit

Pinned installers and config for my coding setup

One release holds T3 Code, the Claude Code CLI, Node, Git, the GitHub CLI, PowerShell 7 and Python at tested versions, the caches those tools would otherwise fetch on first run, and a provisioned WSL distro. Two machines built from the same release are identical, and the install touches the network only to reach whatever model endpoint you point it at.

.\scripts\download-release.ps1 -To C:\toolkit-assets
.\scripts\unpack-release.ps1 -From C:\toolkit-assets
.\scripts\install-windows.ps1
.\scripts\setup-wsl.ps1
sudo bash scripts/install-linux.sh
Download the latest release assets first. unpack-release.ps1 sorts them back into the folder layout; the install script then installs the apps, restores the caches and sets the environment variables that turn off their updaters and telemetry. Open a new terminal afterwards.

Why

One version of everything

Each tool here fetches something on first run: an updater, a headless browser, a device agent, a model manifest. On a machine that should stay on a known build, or reach only one endpoint, those fetches are a problem. This bundles them, so the only thing the install downloads is nothing.

The Claude Code provider's endpoint is set per instance in T3 Code. Templates for an Anthropic-compatible gateway, Bedrock and Vertex are in config/claude-provider-env.example.

Platforms

Three targets, one layout

The folders in the repo mirror the release assets: windows, linux, wsl, caches. Pick the platform, download its assets, run its script.

  1. Windows. The install script installs the apps silently, restores the tool and browser caches, and sets the environment variables.
  2. WSL. setup-wsl.ps1 installs the WSL platform from the bundled MSI and imports a distro that already has Git, Node, the GitHub CLI and the Claude Code CLI inside it.
  3. Linux. install-linux.sh installs T3 Code from the deb and provisions the same tools on a standalone Debian or Ubuntu machine.

Tested on

  • Windows 11 Pro 26300 · Windows PowerShell 5.1: the bake, collect and pin checks run here
  • Ubuntu 24.04 noble under WSL 2: the distro is baked and its contents verified here
  • Not tested: a full install from the release assets on a second machine, end to end

Known issues

  • The app installers use silent flags that are correct for the pinned versions; a newer installer may change them.
  • Importing the raw Ubuntu rootfs instead of the baked distro needs a network to fetch Playwright browsers.
  • T3 Code pins its on-demand tool versions per build. After bumping T3, run scripts/check-pins.ps1 -Fix or the cache is ignored and a download is attempted.
